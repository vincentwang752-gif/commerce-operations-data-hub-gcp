# 广告生产环境安全规范

## 安全边界

广告数据同步与广告投放操作必须使用不同身份、不同权限和不同执行路径。

同步任务只能：

- 读取账户、Campaign、Ad Group/Ad Set、Ad、Creative 和 Insights/报表数据；
- 写入 BigQuery、Airtable 和同步日志；
- 读取用于关联红人、内容和订单的稳定平台 ID。

同步任务不能：

- 创建、修改、启停或删除任何广告对象；
- 修改预算、出价、受众、素材、落地页或投放排期；
- 上传客户名单、离线转化或增强型转化；
- 修改账户成员、资产授权、支付信息或 API App 权限；
- 通过浏览器录制、模拟点击或页面抓取代替官方报表 API。

## 权限设计

### Google Ads

- 使用公司控制的 MCC 和开发者令牌。
- 为同步身份授予目标广告账户的只读权限。
- 固定允许访问的 Customer ID 清单，未登记账户拒绝同步。
- 查询只使用 GAQL `SELECT`；同步代码不得引入 `mutate` 或转化上传接口。
- 开发和验证使用测试账户；生产账户只跑只读报表查询。

### Meta Ads

- 使用公司 Business Manager 下专用于报表读取的 System User/App。
- 仅授权指定广告账户和报表读取所需权限。
- 数据任务只允许读取 Campaign、Ad Set、Ad、Creative、Insights 和合创广告身份信息。
- 如果未来确实需要广告管理能力，必须新建独立身份和独立服务，不能扩大现有同步身份。

## Google Cloud 运行规则

- Secret 全部保存在 Secret Manager，不放在环境文件、日志或 Git。
- 开发、测试和生产至少使用不同服务账号；条件允许时使用独立项目。
- Cloud Run 默认私有，只允许 Cloud Scheduler 和指定管理员调用。
- 默认配置为 `READ_ONLY=true`；没有显式只读配置时服务拒绝启动。
- 生产定时任务固定读取已成熟日期；回填必须显式指定起止日期和账户。
- 每次运行记录账户、日期、请求类型、返回行数、写入行数和错误，不记录 Token 或客户信息。
- 发布使用固定 Git Commit/Tag；不能从未提交的本地代码直接更新生产。

## 上线闸门

必须同时满足以下条件：

- [ ] 账户在批准清单中，账户类型、币种和时区已确认。
- [ ] 同步身份为只读，未复用日常投放管理员登录。
- [ ] Dry Run 没有写入广告平台。
- [ ] 代码通过广告只读策略检查。
- [ ] 稳定键和重复运行验证通过。
- [ ] 平台数据与后台抽查差异在可解释范围内。
- [ ] 合创广告未知红人进入人工确认，不自动合并。
- [ ] Secret 未出现在 Git、日志或截图中。
- [ ] 有上一版本和回滚方法。

## 需要立即停止同步的情况

- 出现任何广告修改、预算变化或状态变化的 API 请求；
- 读取了未登记的广告账户；
- Token、Secret 或用户数据进入日志或 Git；
- 请求量突然显著上升或出现连续权限错误；
- 日级花费重复累计、币种混用或账户时区错位；
- 合创广告被错误关联到已有红人并影响收入归因。

处理顺序：暂停 Cloud Scheduler → 禁用同步服务账号或 Token → 保留日志 → 回滚上一版本 → 对账受影响日期。不要因为数据同步异常去启停广告 Campaign。

## 生产变更审批

若未来确实需要通过代码修改广告，必须作为独立项目处理，并满足：

1. 使用独立服务身份，不复用只读同步身份；
2. 明确单次修改的账户、对象 ID、字段和预期值；
3. 先在测试账户验证；
4. 由广告负责人和账户管理员双重确认；
5. 保留修改前快照、执行日志和回滚动作。
