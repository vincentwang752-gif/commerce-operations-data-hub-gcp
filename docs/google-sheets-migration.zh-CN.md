# Google Sheets 迁移执行记录

## 目标

Airtable 订阅预算未获批准，现有写入受限。将 Google Cloud 同步服务的业务记录写入 Google Sheets，暂不建设汇总界面。迁移期间保留源表，不把旧数据删除当成迁移步骤。

## 已确认的实现范围

| 数据 | 现有实现 | 迁移要求 |
| --- | --- | --- |
| 订单和客户 | Shopify Flow → API Gateway → Cloud Run | 保留入口、校验和字段映射；用稳定订单 ID、客户 ID 更新 |
| Collabs 红人和归因 | 与订单服务共用入口 | 保留红人、订单及触点关联；未知来源不能自动当成确定归因 |
| 问卷和延保 | Apps Script → VOC Cloud Run → Airtable / Klaviyo | 订单匹配和完成状态一并迁移；已有问卷不得因搬表重复发完成邮件 |
| GA4 | Data API → BigQuery → Airtable | 保留 BigQuery 和 T-4 窗口，替换表格写入 |
| Google Ads | 同事分支提供只读 dry-run 连接器 | 当前没有生产写入或调度；需补写入，不能称为已迁移 |
| Meta Ads | 主分支包含字段和安全规范 | 需要广告负责人确认实际连接器状态 |
| 内容资产及人工资料 | Airtable 人工维护 | 迁移现有记录和注释；保留独立人工维护字段 |

## 数据完整性要求

- 一次性搬表必须保留原记录 ID 和跨表关系，并对每张表核对记录数及主键重复。
- 新订单、问卷先恢复增量，再按真实停写时间核对缺口；不默认重新拉取全部历史订单。
- 日期、金额、布尔值与 ID 分开处理，订单 ID 不得被科学计数法或数值精度改变。
- Sheets 使用 RAW 写入文本，客户输入以 `=` 开头时不能被解释为公式。
- 同一业务键重复执行只能更新，不能新增重复行。
- 问卷阶段二完成后，阶段一重试不能把延保总天数从 360 降为 180。
- 只有表格写入完成才能回报同步成功；外部事件已接收不等于表格已保存。
- 迁移回填只搬记录，不触发 Klaviyo 邮件。失败问卷的事件重试继续使用原唯一 ID。
- 人工备注和审核状态不能被整行覆盖更新抹去。
- GA4 与 Shopify 的平台口径区别保留在字段说明中。

## 切换前检查

1. 核对 Cloud Run 实际配置和源代码版本。
2. 建立公司账号拥有的 Sheets，确认运行服务账号能读写指定表格。
3. 建立稳定键、类型和关联映射，并实现并发写入防重复。
4. 完成现有记录导入和数量核对。
5. 验证订单更新、重复事件、问卷阶段顺序和写入失败处理。
6. 切换现有服务，保持 Shopify Flow 和问卷入口兼容。
7. 核对各服务真实写入结果，并记录尚未实现的广告和人工数据源。

## 运行与维护

- `SHEETS_STORE_URL` 指向私有 Cloud Run 网关，调用者使用运行服务账号的 ID Token。网关使用被明确共享的公司表格，不开放匿名调用。
- 表名、表头和 `记录 ID` 是同步契约，不能直接更名、删除或手填重复 ID。人工备注可编辑；服务仅更新提交的字段。
- 使用稳定业务键幂等写入，新增记录保留确定性的 ID，自动编号在锁内递增。跨表链接保存为 ID 数组；客户生命周期反向查询由网关计算。
- 其他原 Airtable 公式、汇总和反向链接的导入值只是快照，尚未完整重建实时计算。当前范围是恢复源数据同步，不能把它们当作实时汇总指标。
- 单实例、单并发之外，以专用 GCS 对象锁避免新旧 revision 重叠写入。锁不自动过期；若进程异常退出遗留锁，先确认没有运行中的写入，再由管理员按 generation 删除指定锁对象，不能无条件自动清锁。
- 用 `scripts/check_sheets_gateway.py --url <private-url>` 检查读通；加 `--verify-write` 只将已有客户业务键原值写回并验证，不发邮件。
- 回退使用迁移前备份中的明确 revision，将流量切回；不要依赖 `latest` 猜测。源 Airtable 未删除，但原套餐写入限制仍存在。
- Google Ads / Meta Ads 只迁移已有记录，持续写入需要广告负责人接入新存储地址。不能把广告历史导入称为广告自动同步已上线。
- 停写期间的缺口与本次源表迁移是两件事；需按失败事件与时间窗口补数，不默认回放全部历史事件。
